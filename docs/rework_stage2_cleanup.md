# Rework: этап 2 — очистка legacy

Дата: 28.09.2026. Базовая версия: 5.1.2.
Точка сравнения: `8394f34c82d5ffab51b9c3fa75c71cd909d7dfe6`.
Изменения выполняются в `rework`; `main` не изменяется. Для последующих
сравнений используется этот SHA, поскольку сама ветка `main` может продвинуться.
Удалённые `main` и `rework` проверены через `git ls-remote`: обе указывают на
этот SHA. Локальная `main` пока старее (`4f564453196467872816d5961d47a2c7e32d2ecb`)
и в этой задаче не передвигалась; для сравнения брать зафиксированный SHA.
По подтверждению владельца все используемые клиенты обновлены до 5.1.2.
AntV уже входит в исходное состояние и сохраняется.

## Метод отбора

Перед удалением проверены ссылки в отслеживаемом коде, тестах, сборке и скриптах
через `rg`, а также объявления функций/классов через AST. Единственное вхождение
имени служило кандидатом для ручной проверки, а не автоматическим разрешением
на удаление. Для обёрток проверены каноническая реализация и её потребители;
динамические строковые импорты также входят в поиск.

## Сохранено намеренно

- `app/main.py`: часть функций используется единой оболочкой, аварийными
  сценариями, тестами и инструментами. Удаление всего файла или массовый перенос
  обязанностей относится к последующим этапам декомпозиции.
- Миграции медицинской БД, настроек, путей и логов: версия клиента не доказывает,
  что все старые данные и конфигурации уже преобразованы. Рабочая база для этой
  очистки не открывалась и не проверялась на применённые миграции.
- Публичный экспорт `app.paths.get_executable_dir` сохранён: SettingsService
  использует его для исключения старых внешних словарей при импорте настроек.
- Чтение старых архивов, datetime, шаблонов назначений и аварийных данных:
  эти форматы остаются частью сохранённой истории.
- В updater сохранены распознавание старых процессов, перечень управляемых
  старых EXE, их очистка, fallback перезапуска и rollback установки.
- Старые ярлыки, discovery каталога `UPD`, формат manifest и конфигурация
  установленного приложения сохранены: возраст файла не делает его ненужным.
- SQLite/SMB, snapshot/replica, блокировки, очереди записи, повторные попытки и
  клиническая логика не упрощались на этом этапе.
- Прочие кандидаты без прямых ссылок не удаляются только по результату поиска:
  полный анализ каждого публичного API и методов монолитов продолжится при
  разборе соответствующих модулей.

Полные группы запускаются штатным `scripts/run_ci_checks.py` с отдельными
путями БД и QSettings. Дополнительно для этого прогона перенаправлены профили,
AppData, ProgramData, временные файлы, аварийное хранилище, логи и конфиги путей
в `tmp/rework-checks/env-<группа>`. Отчёты: `tmp/rework-checks/<группа>/`.

При первом общем прогоне выявлены и исправлены:

- потерянный публичный экспорт `get_executable_dir` — восстановлен;
- старые EXE в fixtures safety-сценариев updater — заменены на единый пакет
  без удаления проверок inventory, отказов, блокировок и rollback;
- зависимость теста диагностики ожидания БД от фиксированной паузы — заменена
  Event-синхронизацией. Исходный тест и runtime совпадали с базовым SHA;
  гонка воспроизведена контролируемо в законной фазе retry-backoff. Проверки
  двух вызовов, четырёх SQLite lock-ошибок, единственной итоговой ошибки,
  приватности и записи после rollback сохранены. Файл: 6/6; контроль с
  искусственной задержкой рабочего потока 350 мс прошёл. Runtime не изменён.

Также убран лишний override аварийного корня из внешней тестовой оболочки:
сценарий default-path проверяет путь внутри уже изолированного ProgramData.

Итоговые результаты:

## История этапа и восстановление

Изменения этого этапа и этот отчёт сохраняются одним коммитом в `rework`.
`main` остаётся исходной версией до отдельного решения владельца после проверки
всех этапов. Слияние, релиз и публикация программы этим коммитом не выполняются.
Последующие этапы следует фиксировать отдельными коммитами с собственными
отчётами: это позволяет сравнить этапы и отменить конкретное изменение.

Найти коммит, зафиксировавший этот этап:

```powershell
git log --diff-filter=A --format="%H %s" -- docs/rework_stage2_cleanup.md
```

Посмотреть исходное содержимое удалённого файла без изменения рабочего дерева:

```powershell
git show 8394f34c82d5ffab51b9c3fa75c71cd909d7dfe6:run_doctor.py
```

Для возврата отдельного файла используется `git restore --source=<SHA> -- <путь>`
в рабочей ветке с последующей проверкой зависимостей и отдельным коммитом.
Для отмены целого этапа — `git revert <SHA-коммита-этапа>`: это добавляет
обратный коммит и сохраняет историю. Если последующие этапы уже меняли те же
участки, сначала нужно согласовать их зависимости и разрешить конфликты.
Возвращать один удалённый файл без проверки импортов и вызовов недостаточно.

Git хранит исходники и отчёты; он не является резервной копией рабочей БД.
Локальные подробные логи в `tmp/rework-checks` не входят в репозиторий;
существенные результаты и ограничения проверки зафиксированы выше.

# Светлая и тёмная темы RemCard

Режим выбирается переключателем «Светлая / Тёмная» в карточке «Цветовая тема»
раздела «Настройки → Интерфейс». Он действует на открытые окна приложения и сохраняется локально для
следующего запуска. Первый запуск использует светлую тему.

## Быстрое отключение

Переменная запуска `REMCARD_FULL_RUNTIME_THEME=0` отключает механизм тем и
скрывает переключатель. После изменения переменной необходимо перезапустить
приложение. Значения `false`, `no`, `off` также отключают механизм; отсутствие
переменной включает его. Этот аварийный флаг сохранён намеренно.

Выбор режима хранится в `%LOCALAPPDATA%\rem_card\appearance\style_settings.json`.
Для изолированных проверок путь задаётся через `REMCARD_STYLE_SETTINGS_PATH`.
Настройки темы больше не требуют доступа к общей SQLite-базе. Старые общие
настройки не удаляются; расположение настроек фона и компоновки не переносится.

## Устройство

- `ui/styles/theme_presets.py`: светлая палитра, согласованная тёмная палитра
  `DARK_PALETTE`, семантические токены и отдельные цвета медицинских графиков.
- `ui/styles/theme_manager.py`: загрузка локального выбора, применение QPalette
  и сигнал `theme_changed`. В тёмной теме используется встроенный Qt Fusion;
  в светлой возвращается исходный нативный стиль. Общий QSS для всех контролов
  не применяется: он удорожал создание дерева карточки.
  Идентичные роль, режим и токены повторно не применяются.
- `ui/styles/theme_runtime.py`: единая точка назначения локальных стилей.
  `set_widget_style(widget, source)` хранит исходный светлый QSS и меняет только
  его цвета. Геометрия, изображения и исходное светлое оформление сохраняются.
  Для дополнения или копирования стиля используется `source_style(widget)`,
  чтобы уже преобразованные тёмные цвета не попали в светлый оригинал.
- Компоненты с собственной отрисовкой регистрируют слабый callback через
  `register_theme_callback`. Графики меняют кисти, оси и линии существующих
  элементов, не перечитывая клинические данные.
- `ui/shared/theme_switch.py`: клавиатурно доступный переключатель без анимации.
- `ui/shared/themed_html.py`: экранная копия HTML-отчётов с цветами текущей темы.
  Исходный HTML и данные для экспорта сохраняются. Готовые изображения графиков
  внутри отчёта остаются изображениями и не перекрашиваются CSS.

Совместимость с многочисленными существующими локальными QSS обеспечивается
центральным преобразованием цветовых свойств. Это позволяет сохранить светлый
интерфейс без одновременной переработки геометрии всех окон. Старые литералы
в исходных светлых стилях ещё существуют; новые компоненты следует описывать
через семантические токены. Старый редактор произвольных схем не является
пользовательским входом нового переключателя.

## Производительность и проверка

Реестр использует слабые ссылки, кэши ограничены. Повторное назначение такого
же QSS пропускается. Переключение обновляет только зарегистрированные стили и
  отрисовку; обычное обновление данных не запускает обход дерева всех виджетов.
Печать документов сохраняет своё светлое оформление.

`scripts/theme_preview.py` создаёт галерею контролов и диагноза.
`scripts/theme_card_preview.py` открывает настоящий `DoctorRemCardWidget` с
временной синтетической базой и изолированными настройками. Он поддерживает
`--platform windows`, `--mode light|dark|both`, `--runs`, `--tab` и `--baseline`.
Последний параметр предназначен для сравнения с копией исходного дерева до
изменений. Сравнивать нужно одинаковые платформу, вкладку и число повторов;
время подготовки схемы БД приводится отдельно от открытия карты.

Тесты темы включены в группу `ui`; CI-runner направляет настройки темы в
временную папку. Проверяются сохранение режима, аварийное отключение,
обратимость светлых стилей, отсутствие удержания окон реестром, переключатель
и изменение цветов графика без повторной загрузки его данных.

## Результат проверки 13 сентября 2026

На Windows, с временной синтетической БД, выполнено по 10 последовательных
открытий полной врачебной карты. Исходное дерево — `80a04ec3`; одинаковый
сценарий запускается отдельно для исходной, новой светлой и тёмной темы.
Между повторами Qt-окно удаляется с проверкой `DeferredDelete`. Параллельные
тесты на время замера остановлены. Каждый повтор дождался снимка карты и
витальных данных; дальнейшие асинхронные обновления соседних секторов не входят
в измерение первого кадра.

| Медиана, мс | Исходная версия | Новая светлая | Тёмная |
|---|---:|---:|---:|
| Создание и синхронная загрузка карты | 717 | 583 | 585 |
| До снимка карты с витальными данными | 833 | 690 | 692 |
| До первого отрисованного кадра | 1009 | 860 | 848 |

Переключение отдельной открытой карты: 212 мс на смену режима, 124 мс на
отрисовку. Подготовка схемы БД и сохранение PNG исключены из времени кадра.
Это локальный стенд с одной синтетической картой, а не замер рабочей базы
по SMB или гарантированное время на других компьютерах.

Функциональные группы: UI — 714 тестов, core — 751 тест; статический анализ
и восемь архитектурных проверок успешны. Дополнительно выполнена нативная
серия из 100 переключений с созданием сектора 8, клавиатурой и QAccessible.

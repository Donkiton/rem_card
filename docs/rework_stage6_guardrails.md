## Изменения этапа

Новые ограничения включаются в существующий `quality` через
`architecture_safety_check.py`. Они проверяют исходники без запуска приложения,
Qt и открытия баз данных. Удалённые модули совместимости не должны появляться
снова или использоваться в импортах; разобранные входные модули не должны
незаметно превращаться обратно в монолиты. Подробности и границы проверки —
в [architecture_guardrails.md](architecture_guardrails.md).

GitHub workflow Tests дополнен запуском при push в `rework`. Существующие
проверки `main`, PR и ручной запуск сохранены. Изменение вступит в силу после
отправки шестого этапа; локальные результаты ниже не являются результатом
GitHub Actions.

В регрессионном сценарии `orders_finish_after_content_hash_guard` фиксированное
ожидание 160 мс заменено ожиданием фактического состояния с дедлайном 2 секунды.
Задержанная финализация освобождается при выходе, поток завершается до
восстановления подменённых зависимостей. Пороги и реализация рабочего watchdog
не менялись. Дополнительные тесты подтверждают, что задержка планирования
потока на 250 мс допустима, а отсутствие watchdog по-прежнему проваливает
сценарий. Это устраняет причину нестабильности, отмеченную на пятом этапе,
сохраняя проверку отмены и отбрасывания позднего результата.

## Проверки и ограничения

Итоговые запуски выполняются на отдельных BAZA, QSettings, профилях, каталогах
логов/Temp и конфигурациях темы под `tmp/rework-stage6-checks`. Рабочая база
не используется. Для UI включён `REMCARD_RUN_ANTV_SMOKE=1`.

| Проверка | Результат |
|---|---|
| Полный core | 1052 passed, 56 subtests passed |
| Полный UI, включая реальный offline AntV smoke | 979 passed, 11 subtests passed |
| Полный regression fast | 538/538, без падений и повторных запусков |
| Flake8, BOM, Radon | 3/3 |
| Архитектурные ограничения | 10/10 |
| Проверка полноты отчётов общим CI-валидатором | 2031 pytest-тест, 538 safety-сценариев; без пропусков и дубликатов |

Новые ограничения проверены на корректных и нарушающих правила временных
исходниках: прямые/относительные импорты с псевдонимами, восстановленные файлы,
синтаксическая ошибка, ложные совпадения в тексте и точная граница числа строк.
Эти тесты и оба новых сценария watchdog входят в полный core-прогон.

Первый UI-прогон пересёкся с добавлением нового core-теста до его регистрации
в `groups.json`: вложенный pytest в проверке изоляции файловых диалогов
отказался запускаться из-за неполного инвентаря. После завершения регистрации
весь UI-набор повторно прошёл на неизменных исходниках; итоговые числа в таблице
относятся к этому прогону. Повтор не связан с падением нативного процесса.

Независимый просмотр изменений принят без блокирующих замечаний. Ограничения
статического анализа и необходимость отдельной эксплуатационной приёмки
сохраняются.

Полная ручная приёмка четырёх ролей, визуальное сравнение на рабочих экранах,
сборка EXE и сетевой стенд с несколькими клиентами остаются отдельной приёмкой.
Замеры ускорения относительно main не проводились. Успешные автотесты не
означают, что эти проверки выполнены.

## Дальнейшая работа и откат

Точка входа из исходников сохраняется: `python run_remcard.py`.
Новые обязанности следует добавлять в соответствующий функциональный модуль,
а изменение общего состояния примесей проверять по всем его потребителям.
Лимиты нельзя повышать только ради зелёного статуса: изменение границы
ответственности должно быть объяснено в diff и проверено.

Для просмотра прежнего файла: `git show <SHA>:<путь>`. После сохранения шестого
этапа отдельным коммитом его можно отменить через `git revert <SHA-этапа-6>`.
Отмена нескольких этапов выполняется в обратном порядке с повторными
проверками, поскольку более поздние изменения зависят от ранних.
Миграции рабочих данных этими ограничениями не выполняются и не откатываются.

`main` сохраняется до отдельного решения о слиянии после приёмки. Этот этап
не включает слияние, релиз или публикацию обновления клиентам.

# 機能とワークスペース

## ひとつのワークフローに参加する役割

- <strong>医師</strong> — 入院と病床、勤務帯ごとの患者記録、指示とテンプレート、食事指示、処置、転帰、アーカイブ、レポート、計算ツール。
- <strong>看護師</strong> — 直近の指示、実施記録、実際の栄養摂取量、勤務帯ごとの推移、印刷、業務統計。
- <strong>手術室</strong> — 緊急・予定手術、簡易指示、薬剤、手術の段階とイベント、集中治療部門（РАО）と手術室の間の患者移動、症例の終了、レポート。
- <strong>管理者</strong> — 統合設定センター、現行・アーカイブデータベースの状態、バックアップ、マスターデータ、印刷、外観、診断。

## 現行バージョンの機能

### バージョン5.1の統合アプリケーション

医師、看護師、予定手術室、緊急手術室の各画面を共通のウィンドウから開けます。役割を切り替えると、アプリケーションは受け付け済みの書き込みを完了し、前のセッションのリソースを解放します。データベースの確認と端末の準備では進行状況が表示され、ログインを中止することもできます。起動診断は、アプリケーションや役割画面が開くまでの遅延を調べるために利用できます。

データフォルダーの設定はアプリケーションに組み込まれています。共有のメンテナンスモードが、各端末によるデータベースへのアクセスを調整します。中央データベースに接続できない場合、緊急ログインではローカルコピーの有無、使用可能性、経過時間を確認します。ネットワークモードへの復帰と変更の移送は、専用の手順で実行します。

### 患者記録と勤務帯の業務

患者記録には、指示と実施状況、バイタルサインとグラフ、水分投与量と排出量、人工呼吸、処置、臨床検査、臨床イベントがまとまっています。現在、前日、予定の記録への移動はそれぞれ区別され、患者の履歴はアーカイブから確認できます。指示では、薬剤・溶解液・投与経路のマスターデータ、テンプレート、勤務帯ごとのスケジュールを使用します。

<strong>「食事」（Диета）</strong>タブでは、医師が栄養計画を設定し、編集可能なテンプレートを適用できます。看護師は実際の摂取量を記録します。摂取を拒否した場合は<strong>0 ml</strong>として保存できます。実際の栄養摂取量は水分出納に反映され、自分の変更を順に取り消すことができます。レコードのバージョン確認によって、別の利用者の変更を上書きしないよう保護されています。

中心静脈カテーテル、腰椎穿刺、輸血などの処置文書と、患者記録および手術症例のPDFレポートを作成できます。

### 計算ツールと熱傷輸液のモニタリング

セクター8の<strong>「計算」（Расчёт）</strong>メニューには、輸液、電解質、熱傷の計算ツールがあります。熱傷計算ツールは、該当するICD診断が登録された患者記録から、医師と看護師が利用できます。

年齢、体重、熱傷面積、受傷時刻を考慮し、第1・第2・第3病日とショック離脱後の期間に対応しています。保存済みの患者記録から実際の投与量と尿量を読み込みます。小児の第1病日および第2〜3病日のモードでは、実際の経腸投与量も考慮します。ウィンドウには、計算対象期間、モニタリング時刻、残りの投与量、計算上の投与スケジュールからのずれが表示されます。記録上の日付と受傷からの経過日数は別々に扱われます。

データは計算ツールを開いた際に読み込まれます。<strong>「記録から更新」（Обновить из карты）</strong>コマンドでは、手動入力としてマークされた値を保持したまま再読み込みできます。読み取りエラーが投与量ゼロとして扱われることはなく、元データを変更すると以前の計算結果は消去されます。計算結果は説明付きでコピーできますが、指示が自動作成されることはありません。詳しい規則と制限は[計算ツールのドキュメント](../burn_infusion_calculator.md)を参照してください。

### 統合アーカイブと分析

アーカイブセンターは、医師、看護師、管理者がそれぞれの役割の権限に応じて利用できます。集中治療部門（РАО）の患者アーカイブ、手術症例アーカイブ、分析、グラフ、統計レポートが統合されています。アーカイブデータベースの患者記録を表示する際は、独立した読み取りサービスを使用します。

分析では、期間と患者群を選択し、フィルターを適用し、表示設定を保存して、期間や患者群を比較できます。各指標について、結果、算出方法、対象症例の一覧を確認できます。共通の指標レジストリが単位、データソース、組み入れ基準を定義し、データ品質チェックが重複や不整合な値を検出します。比較データが存在しない場合は、その旨が明示されます。計算とグラフ作成はバックグラウンドで実行され、レポートとグラフは整合した分析用スナップショットを使用します。

指標の定義と技術検証の範囲は、[分析の臨床契約](../analytics_clinical_contract.md)と[実装マトリクス](../analytics_implementation_matrix.md)に記載されています。

### 手術室、設定、診断

緊急手術と予定手術の業務画面では、チーム、麻酔管理、手術の段階、測定値、薬剤、簡易指示を含む手術症例を管理できます。集中治療部門（РАО）からの患者移動は、患者の所在管理と手術室での受け入れに連動します。ネットワーク障害時には、手術室専用の機能を制限したローカルモードを利用できます。そのデータは、接続復旧後に専用の移送手順を通じて取り込みます。

設定センターには、マスターデータ、手術室の設定、栄養テンプレート、検査カタログ、印刷、テーマ、背景、データベースのメンテナンスがまとまっています。利用者からの問い合わせには診断ログを添付できます。技術ログにはローテーション、保存期間、容量上限が設定されています。頻繁に記録される通常のメトリクスは1分単位の要約にまとめられ、繰り返すエラーは状況情報を含む簡潔な記録に集約されます。医療データ変更の監査記録は、技術ログや同期通知とは別に保存されます。

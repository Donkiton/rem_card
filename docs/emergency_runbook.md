# Аварийная инструкция

## Аварийная работа медсестры

Работать следует на подготовленном ПК медсестры. При запуске без сети RemCard предлагает ввести аварийный пароль и открывает проверенную локальную копию с пациентами. Без подходящей копии вход запрещён; пустая база не создаётся. Остальной персонал не должен изменять основную базу до завершения переноса.

В едином окне аварийная копия обновляется только во время сетевой работы в роли медсестры, на любом ПК. Врач при обрыве получает указание продолжить работу на ПК медсестры и возвращается к выбору ролей. Выбор роли медсестры на этом же ПК разрешает переход только при наличии подходящей копии и после ввода аварийного пароля. Новая сессия открывается после безопасного перезапуска; роль сохраняется. В уже активную сессию этого ПК можно войти врачом или медсестрой без повторного аварийного пароля.

Перед запуском RemCard показывает дату последнего обновления аварийной копии, её возраст и допустимый предел — по умолчанию 3 суток. Просроченная, отсутствующая, повреждённая или датированная будущим копия не используется. Сама проверка ничего не удаляет: файлы остаются для разбора или последующего безопасного обновления. Если до потери сети достоверно известно больше изменений основной базы, чем попало в копию, RemCard также показывает это известное расхождение.

Чтобы закончить смену до восстановления сети, закрыть RemCard: локальная сессия и принятые записи сохраняются. При следующем запуске любой роли на этом ПК программа сначала откроет сохранённую аварийную сессию.

Для переноса нажать **«Аварийный режим»** в секторе 8 у врача или медсестры. По умолчанию кнопка находится слева рядом с репортом. В настройках отображения интерфейса её можно включить или скрыть, переместить между сторонами и изменить порядок отдельно для каждой роли. Даже включённая кнопка появляется только во время аварийной работы. В окне ввода пароля сначала проверяется основная база. Подтверждение доступно только после свежей успешной проверки. После подтверждения программа дождётся принятых записей и приостановит ввод; другие окна общей локальной сессии завершат сохранение и закроются. Несохранённый черновик назначений нужно сохранить или отменить.

В окне ожидания доступны **«Проверить связь»**, **«Продолжить работу»** и **«Закрыть RemCard»**. Закрытие сохраняет данные; следующий запуск врача или медсестры на том же ПК возвращает ожидание. Продолжение работы отменяет прежнее разрешение переноса: после новых записей нужен новый просмотр.

При восстановлении сети появляется уведомление **«Перейти сейчас» / «Остаться»**. После выбора «Остаться» оно повторяется через пять минут, пока база доступна и аварийная работа продолжается. Пока уведомление открыто, новое не создаётся.

Исключение — локальный запуск единого окна при полностью недоступной сетевой папке. В нём фоновые обращения к основной базе отключены. Нажатие «Аварийный режим» предлагает безопасный перезапуск для проверки основной базы; если сеть восстановлена, открывается та же аварийная сессия с доступной проверкой и переносом. Если связи всё ещё нет, локальная работа продолжается. Возврат к выбору ролей и повторный вход врача или медсестры в ту же локальную сессию выполняются без перезапуска. Для проверки основной базы нажмите «Аварийный режим» и подтвердите перезапуск; смена среды хранения также требует нового процесса. Само появление сети не заменяет аварийную базу основной и не переносит данные без предусмотренного подтверждения.

## Перенос в основную базу

1. Связь проверяется автоматически; кнопка «Проверить связь» запускает проверку вручную. Проверки устойчивого доступа, целостности и чужих блокировок сохраняются.
2. В окне «Проверка аварийных данных» раскрыть изменения нужного пациента. Указаны ФИО, история и поступление; изменения сгруппированы по разделам, начиная с показателей состояния и назначений.
3. Отметить «Принять локальные данные» для нужных госпитализаций. Ни одна не выбрана заранее.
4. Нажать «Перенести выбранные». Для выбранной госпитализации локальное клиническое состояние имеет полный приоритет, включая отмену сетевых изменений, которых нет локально. Эти различия показываются в просмотре. Невыбранные госпитализации не меняются.
5. Пропуск других госпитализаций требует подтверждения. «Отмена» сохраняет ожидание. «Завершить без переноса» требует отдельного подтверждения и сохраняет аварийную копию в локальном архиве.
6. RemCard закрывает соединения, перезапускается, переносит выбранные записи и открывает основную базу. Если данные изменились после просмотра, потребуется новое подтверждение.

Перенос выполняется SQL-операциями в одной транзакции, с резервными копиями и проверками SQLite. Полная подмена основной базы не является способом объединения. Восстановление из проверенной резервной копии используется только для отката неуспешной проверки результата.

## Прерванный перенос

Локальную аварийную папку не удалять. При неопределённом результате записи RemCard блокирует продолжение локальной работы. После восстановления доступа нажать «Проверить связь»: программа сверит подтверждение транзакции в основной базе и завершит уже выполненный перенос без повторного применения.

Если после начатого переноса утрачен файл решения пользователя или изменился цикл основной базы после ротации, требуется сопровождение администратора. Новая пустая база не заменяет исходный цикл; сначала нужно определить исходную базу и сохранить обе версии данных.

Отсутствие пациентов в исходной копии запрещает создание аварийной сессии. Очистка конкретной карты во время уже подтверждённой аварийной работы рассматривается отдельно и должна быть видна в просмотре. Пустой файл не считается таким решением.

## БД недоступна

1. Не запускать recovery вручную.
2. Проверить доступ к сетевой папке.
3. Проверить права на `<папка данных>/archiv`.
4. Закрыть лишние экземпляры приложения.
5. Повторить запуск.

## БД занята

`locked`, `busy`, `unavailable` не равны corruption.

1. Дождаться завершения операции на другом ПК.
2. Проверить, не открыт ли второй экземпляр на той же роли.
3. Не восстанавливать БД из backup только из-за lock.

## Нужна новая версия

1. Закрыть текущий клиент.
2. Обновить приложение.
3. Запустить снова.
4. Если второй ПК еще старый, обновить и его до открытия БД.

## Recovery warning

Auto-recovery запрещен, если активен второй клиент. В этом случае восстановление выполняется только вручную ответственным после закрытия всех клиентов и проверки backup через `restore_drill.py`.

## Где искать логи

- локальные метрики: локальная папка логов клиента;
- backup/recovery audit: `<папка данных>/logs`;
- backup validation reports: `<папка данных>/backup_health/reports`;
- invalid backups: `<папка данных>/backup_health/invalid_backups`.

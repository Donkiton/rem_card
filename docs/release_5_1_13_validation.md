# Приёмка 5.1.13 без обновления общей базы

Дата подготовки: 2026-10-28.

## Контракт совместимости

- Версия программы: 5.1.13.
- Схема общей медицинской базы: 28, без новых DDL, индексов и миграций.
- Минимальная версия клиента: 5.1.11, без повышения политики доступа.
- Профиль готового пакета: `REMCARD_BUILD_NO_DATABASE_UPGRADES=1`.
- В итоговом full-manifest: `database_upgrades_disabled: true`,
  `min_client_version: "5.1.11"`.
- Сборка выполняется штатным `scripts/build_release.py` из точного слитого
  коммита GitHub `main`. Сетевое распространение и GitHub Release выполняет
  владелец проекта отдельно.

`test_compatible_database_and_policy_are_unchanged` теперь проверяет также
клиент 5.1.13: повторный вход не меняет полный SQL dump совместимой базы,
файл политики доступа и не создаёт миграционный backup. Исходники схемы,
миграций и обязательного минимального клиента в этом выпуске не меняются.

## Исправления

### Сетевые проверки при обновлении реплики

Сверка исторических таблиц продолжает учитывать старые UPDATE и DELETE.
Построчные вызовы больше не обращаются к сетевым lock-файлам каждый раз:
проверки writer/rotation выполняются с интервалом 0,1 секунды после завершения
предыдущей проверки. На границах этапов и перед возвратом готового кандидата
они выполняются принудительно. Сохраняются локальная отмена, проверки
источника, quick_check, fsync и удаление невыданного кандидата при отказе.

Интервал опроса не является жёстким пределом самого SMB/SQLite вызова.
Зависший системный вызов по-прежнему ограничивается сроком жизни дочернего
процесса. Полная историческая сверка и её семантика не заменены чтением хвоста.

В существующие `delta_metrics` добавлены `coordination_check_count`,
`coordination_probe_count`, `coordination_probe_ms`. Они позволяют отличить
число дешёвых проверок от количества и времени сетевых опросов.

### Соединения при загрузке назначений

Авторитетная проверка версии, чтение change_log и административной дельты
переиспользуют одно короткоживущее центральное read-only соединение.
Оно работает в autocommit, без длительной read-транзакции и закрепления
устаревшего курсора. Для проверенного supported delta число открытий
сокращается с трёх до одного; при unsupported delta с полным построением —
с трёх до двух. Перед полным построением соединение закрывается.

Проверки cursor floor, epoch и устаревшего снимка сохранены. Ошибка открытия
оптимизирующего scope оставляет прежнюю retry/fallback политику. Время открытия
соединения входит в `version_probe_ms`, а не исчезает из диагностики.

По одному курсору нельзя заранее узнать сущности будущего change_log;
проверка неподдерживаемых сущностей сохранена. Минимизация числа соединений
не означает гарантированного устранения всей задержки файлового сервера.

### Резервное копирование

Алгоритм и тайм-ауты не изменены: исправление остановки и безопасной уборки
worker уже присутствует с 5.1.11. Повторно проверены отказ остановки,
живой/непроверяемый владелец, позднее завершение и уборка только собственных
блокировок. Удаление блокировок другого компьютера по одному возрасту
не добавлялось.

## Проверки исправлений

- 75 тестов: writer probe, replica refresh, worker, copy diagnostics и delta.
- 57 тестов: переиспользование соединения, согласованность кеша/epoch,
  источников снимка и обновления назначений медсестры.
- 17 тестов профиля без миграций, включая неизменность базы и политики для 5.1.13.
- 31 тест суточного backup и отсутствующих отчётов, включая реальные subprocess.

Новые сценарии реплики используют 12 тысяч исторических строк и задержку
1 мс именно у metadata-проверок. Проверяются ограниченное число сетевых
обращений, сохранность старых изменений/удалений, writer/rotation во время
сверки и перед выдачей результата, отмена, удаление кандидата и освобождение
SQLite read locks.

Новые сценарии назначений используют реальные SQLite и DBManager: задержку
открытия, конкурентный commit между probe и change_log, отклонение полного
снимка ниже cursor floor, отмену и очистку после исключений. Это локальный
стенд; ускорение на конкретном сетевом рабочем месте оценивается после установки.

## Полный локальный прогон

Штатный `scripts/run_ci_checks.py` выполнен с тем же составом групп, который
использует GitHub Actions. Каждый runner изолирует профиль ОС, настройки,
каталоги данных и журналы от установленной программы.

| Группа | Результат |
|---|---|
| quality | 3 проверки качества и 10 архитектурных проверок пройдены |
| core | 1558 passed, 1 skipped, 60 subtests passed |
| ui, с `REMCARD_RUN_ANTV_SMOKE=1` | 1146 passed, 17 subtests passed |
| regression, fast | 538/538 пройдены; native crashes и retries отсутствуют |

Единственный пропуск — сценарий перенаправления через symlink: локальная
Windows не предоставляет процессу право создавать символические ссылки.

Независимый review не выявил подтверждённых дефектов; отдельно выполнены
37 новых и совместимых тестов. Готовый пакет дополнительно проходит
обязательные release gates, проверку inventory/SHA-256 и smoke обоих EXE
со сверкой встроенного запрета миграций.

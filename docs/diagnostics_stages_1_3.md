# Диагностика и точечные исправления после аудита 23.09.2026

Единый запуск открывает одну локальную аварийную сессию до создания окна и закрывает её при выходе. Смена роли не создаёт новую аварийную сессию. Стеки UIWatchdog используют уже существующие ограничения количества и размера дампов. Повторный запуск, который только показывает открытое окно, отдельную сессию не создаёт.

## Диагностика врача

Строки `[DoctorNavigation]` в локальных файлах `runtime_doctor_navigation_*.log` содержат переходы экранов, короткий стек вызовов, технический ID госпитализации, вкладку, типы активного/модального окна, фокус и захват ввода. Включаются в существующий сбор логов пользовательского репорта. Используют существующие ротацию и очистку локальных логов, но отдельный поток записи и файл, чтобы не удерживать блокировку общего логгера перед GUI-потоком.

Записываются только технические события. Текст полей, имена объектов, заголовки окон, значения назначений, локальные переменные и строки исходников не собираются. Ограниченный буфер содержит последние 16 действий за 10 секунд: кнопки мыши, навигационные клавиши и запрос «Назад»; обычный ввод текста не сохраняется. Наличие действия в буфере не доказывает причинную связь с переходом.

**Ctrl+Alt+F12** в открытой роли врача делает снимок состояния ввода. События наблюдаются автоматически, нажатие горячей клавиши необязательно. При полностью остановленном Qt event loop эта клавиша не исполняется до его возобновления; для такого случая работает UIWatchdog.

Фильтр не поглощает события и снимается при завершении роли врача. Диск обслуживает один фоновый поток; очередь ограничена 256 записями, поток событий — 20 записями в секунду. Переполнение пропускает диагностику, а не задерживает интерфейс; последующие записи содержат счётчики пропусков. При аварийном завершении последние элементы очереди могут не попасть на диск.

## Ожидание реплик

Повторы `local_replica_sync_deferred` и `sqlite_write_lock_stale_cleanup_skipped` для снимков сводятся в `local_metrics_summary` за 60 секунд. Сохраняются первые события, смена причины/владельца, периодические подробные записи и успешное обновление после ожидания. События `local_replica_snapshot_wait_started` и `local_replica_snapshot_wait_finished` отмечают границы ожидания в процессе; `outcome=interrupted` не означает успешное восстановление. Правила захвата/освобождения блокировок, интервалы копирования и состояние доступности базы не изменяются.

## Точечные исправления

Пустая операция `auto_release_outcome_beds` (результат 0) больше не инициирует принудительное обновление. Реальное освобождение коек и другие операции сохраняют прежнюю логику обновления.

Ошибки времени жизни элементов текущих назначений и фильтра оболочки проверяются на искусственных Qt-объектах. Эти исправления сами по себе не доказывают устранение исходного неожиданного возврата из карты: для него предусмотрена новая диагностика.

Продолжение — [этапы 4 и 5](diagnostics_stages_4_5.md): фоновые чтения и отправка
репорта, независимость реплик. Оптимизация проверки базы при первом входе
(этап 6) остаётся отдельной задачей.

# Проверки выпуска 5.1.17

## Профиль и границы

Выпуск предназначен для уже обновлённой схемы 29. Минимальный клиент — 5.1.15,
production-сборка выполняется с `REMCARD_BUILD_NO_DATABASE_UPGRADES=1`.
Сетевой профиль SQLite сохраняет `DELETE`, `synchronous=EXTRA` и `mmap_size=0`.
Рабочие медицинские данные и сетевой каталог обновлений в приёмке не участвуют.

## Изменённые пути

- Ожидание connection-local readonly PRAGMA вынесено из общего mutex настройки.
  Защита native initialization и настройки writable-соединений сохранена.
- Только известные фоновые чтения монитора и обновления назначений уступают
  локальному writer. Пользовательские click/user/post_finalize и неизвестные
  источники не получают нового ожидания. Сам writer не ждёт синтетический
  reader gate; прежние бюджеты, COMMIT, rollback и подтверждения сохранены.
- Уже начатая явная read-транзакция может закончить вложенное чтение и
  освободить свой SQLite lock. Остановка монитора и отмена snapshot завершают
  ожидание. Подготовка источника назначений измеряется отдельно.
- Проверки карты/дат и настройки PDF выполняются в фоновом подготовительном
  этапе controller, W1-кнопок и обеих вкладок печати. Сохранены отдельный
  коллектор медсестры, параметры клика, single-flight и отмена владельца.
- Навигация переживает эквивалентную замену layout, сохраняя проверки пациента,
  даты, режима, сервиса и поколения. Вкладка назначений различает загрузку,
  ошибку и действительно пустой результат, не показывает другого пациента.
- Диагностика delta отделяет штатный skip от merge/неизвестной ошибки.
  Признаки полной загрузки и fallback продолжают записываться.
- Штатная навигация, GC и обслуживание логов сворачиваются. Ошибки сохранения,
  медленные транзакции, предупреждения и сроки хранения не сокращены.

## Контролируемые измерения

Windows x64, Python 3.11.0, SQLite 3.38.4. Использованы синтетические базы.

| Сценарий | До | После |
| --- | ---: | ---: |
| Независимое readonly-соединение при фиксированном 200 мс ожидании cache_size другого соединения, p95 | 214,427 мс | 1,299 мс |
| Фоновые подготовки соединений, вошедшие во время writer intent | 6 из 6 | 0 из 6 |
| Обычное пользовательское чтение, медиана серий по 2000 SELECT | 0,02741 мс | 0,02709 мс |

Существующий неуступающий SQLite reader сохраняет прежний bounded rollback
writer. Отдельные actual SQLite tests проверяют RESERVED writer, foreground
read, explicit snapshot, adoption ранее начатой транзакции, отмену и cleanup.
Разницу здоровых чтений в микросекундах не следует считать доказанным ускорением.

Матрица кода 5.1.15/5.1.16 и двух фактических окружений проверена на одной
локальной нагрузке: 24 пары изменений, две реплики, 6000 untracked rows.
Во всех четырёх случаях integrity и логическая эквивалентность сохранены.
P95 записи врача/медсестры составили 18,413/18,420; 19,237/19,568;
18,373/19,107; 18,798/16,183 мс соответственно. Производственные задержки
10–20 секунд на этой нагрузке не воспроизведены. Основания объявлять pandas
единственной причиной или откатывать его по этим данным нет.

Отдельная приёмка SMB использует разрешённый пользователем изолированный
сетевой QA-каталог и синтетические данные. Центральный файл сетевой,
профили и реплики локальные; два worker-процесса на одном ПК используют
разные имитированные host gates. Это не измерение работы двух физических
рабочих мест. Финальные результаты находятся в отчётах приёмки выпуска.

## Объём логов

В профильных fixtures 7200 обычных focus-событий дали 12 сводок и кольцо
64 событий вместо полного потока; payload уменьшился с 3004657 до 2315 байт.
Полный контекст остаётся для аномалии, ручного снимка и временного detail-mode.
Смешанный fixture метрик уменьшился с 514400 до 27194 байт с точными
count/raw_count/гистограммами. Эти отношения относятся к выбранным потокам,
а не обещают такое же уменьшение всей папки логов.

Обычные replica-lock summaries имеют окно 300 секунд, остальные окна не
изменены. Для подсчёта операций использовать count из summary: raw records
уже входят в него и повторно не прибавляются. Отметка перед full GC и
подробности медленного/ошибочного GC сохранены. Клинический audit и
недоставленные crash-материалы не очищаются ради уменьшения объёма.

## Проверки и сборка

Используются `scripts/run_ci_checks.py quality`, `all` и `regression`, а также
независимый review неизменяемых diff. В первоначальном полном прогоне прошли
2984 tests и 77 subtests, один тест пропущен. После замечаний review
затронутые сценарии проверяются повторно, а финальный PR проходит полный CI.

Сборщик отклоняет несовпадение фактических зависимостей с requirements до
компиляции. После PyInstaller он читает версии pandas, NumPy и PySide6 из
самого EXE без исполнения модулей, записывает их и полный список installed
distributions в manifest. Приёмка full ZIP, обоих EXE и установщика RU/EN
выполняется по `docs/windows_installer.md`; точный source commit и SHA-256
фиксируются в отчётах и assets релиза.

Эти проверки закрывают обнаруженные программные механизмы. Они не доказывают
устранение всех SMB-задержек в рабочей среде. После установки следует сравнить
несколько дней логов по времени сохранения, отказам и показу назначений.

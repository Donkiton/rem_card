# Smoke-чеклист аварийного режима

Все проверки выполнять на синтетических данных в отдельной папке. Проверить фактические пути медицинской базы, настроек, локальной аварийной сессии и логов. Рабочую базу не отключать, не копировать и не переименовывать ради теста.

## Запуск и интерфейс

| Сценарий | Ожидаемый результат |
| --- | --- |
| Обычный запуск медсестры | Кнопка аварийного режима скрыта, standby подготовлен |
| Нет сети, подготовленный ПК | Кастомное предложение и видимое окно пароля; настройки читаются локально |
| Неверный пароль / ошибка проверки | Сообщение в том же окне; ввод можно повторить |
| Нет standby / пустой / повреждённый standby | Вход запрещён, пустая база не создаётся |
| Врач без сети, аварийная сессия ещё не создана | Кастомное сообщение о работе на ПК медсестры |
| Врач на ПК с активной/ожидающей локальной сессией | Открывается общая локальная сессия, даже при доступной сети |
| Повторные фоновые ошибки 15 минут | Одно уведомление об инциденте, вложенные окна не накапливаются |
| Закрыть врача и сразу запустить снова | Ожидание завершения предыдущего процесса; второго писателя нет |
| Аварийная работа обеих ролей | В секторе 8 кнопка «Аварийный режим» с emergency_mode.png, без tooltip; по умолчанию слева рядом с репортом |
| Настройки кнопки аварийного режима | У врача и медсестры отдельно сохраняются видимость, сторона и порядок; отключённая кнопка скрыта, включённая появляется только в аварийном режиме |
| Windows 100% / 150% | Текст и отметки выбора видны; клавиатура работает |

## Ожидание и просмотр

| Сценарий | Ожидаемый результат |
| --- | --- |
| Пауза с выполняющейся записью | Принятая запись завершается до просмотра |
| Диалог пароля до паузы | Подтверждение заблокировано до свежей успешной проверки основной базы; ошибка/таймаут показаны в том же окне |
| Первый успешный раунд ещё не подтвердил устойчивость | Диалог дождётся следующих раундов и разблокирует подтверждение |
| Возврат сети, «Остаться», несколько периодов по 5 минут | Повторное напоминание, одновременно не более одного окна |
| Выход из любой роли при двух локальных окнах | Другое окно сохраняет записи и закрывается до просмотра/переноса; черновик требует решения |
| Завершение начато одновременно в двух окнах | Завершением владеет одно окно; второй перенос не запускается |
| Старый nurse.lock от завершённого процесса этого ПК | Устаревшая блокировка снимается; живой процесс/неизвестный владелец не затрагиваются |
| Запись прошла проверку, но ещё не попала в очередь | Пауза ждёт постановку и выполнение записи |
| Два запроса паузы одновременно | Второй не принимает незавершённую остановку за готовую |
| Закрыть RemCard во время ожидания | Следующий запуск того же ПК возвращает ожидание |
| «Продолжить работу» | Запись снова доступна; прежнее разрешение переноса отменено |
| Сеть восстановилась / ручная проверка | Один просмотр после проверок; записи в основную базу до подтверждения нет |
| Новый пациент, показатели, назначения, питание, ИВЛ, процедуры, исход | Понятные изменения по госпитализациям и разделам |
| Выбрать часть пациентов | Переносятся выбранные; пропуск остальных требует подтверждения |
| Отмена / отказ от всех изменений | Отмена сохраняет ожидание; отказ сохраняет локальный архив |
| Неизвестное клиническое поле/формат | Перенос блокируется; данные не скрываются молча |

## Целостность переноса

| Сценарий | Ожидаемый результат |
| --- | --- |
| Сетевая запись изменилась после standby | Для выбранной госпитализации побеждает локальное состояние |
| Сетевая отметка выполнения отсутствует локально | Различие показано до подтверждения |
| Совпали ID независимых новых пациентов | ID и зависимые ссылки согласованы, пациенты не смешиваются |
| Прежняя госпитализация на той же койке | История не блокирует текущую запись и не меняется без выбора |
| Общие сведения пациента / койка / шаблон питания | Невыбранные данные не изменяются через общую ссылку; зависимость проверяется |
| Ротация / другая база по прежнему пути | При несовпадении цикла перенос запрещён |
| Другой процесс держит doctor.lock | Перенос блокируется без изменения БД; после освобождения проверка продолжается |
| Данные изменились после просмотра | Контрольная сумма не совпадает; нужен новый просмотр |
| Ошибка резервной копии до транзакции | Основная БД неизменна, можно вернуться к локальной работе |
| Ошибка SQL внутри переноса | Нет частично применённого набора; FK и SQLite проходят проверки |
| Обрыв после COMMIT до локального завершения | Результат определяется по записи транзакции, повторного применения нет |
| Основная база недоступна при неопределённом исходе | Локальная запись запрещена до выяснения результата |

Проверять quick_check, integrity_check, foreign_key_check, сохранность настроек и архив аварийной сессии. Профиль общей SQLite: journal_mode=DELETE, synchronous=EXTRA, mmap=0.

## Команды

CI-runner задаёт временные пути данных и настроек:

```powershell
.venv\Scripts\python.exe scripts/run_ci_checks.py core
.venv\Scripts\python.exe scripts/run_ci_checks.py ui
.venv\Scripts\python.exe scripts/run_ci_checks.py quality
.venv\Scripts\python.exe scripts/run_ci_checks.py regression
.venv\Scripts\python.exe scripts/emergency_db_acceptance_runner.py
```

Основные тесты: test_emergency_authoritative_merge.py, test_emergency_workflow.py, test_emergency_workflow_ui.py, test_emergency_outage_ui.py, test_emergency_review.py, test_emergency_review_ui.py; восемь сценариев acceptance-runner и регрессионные проверки startup/standby/merge.

SMB через \\localhost\C$ проверяет UNC-пути и отдельный процесс на этом ПК. Это не заменяет двухкомпьютерный стенд с реальным обрывом сети/питания. Для такого стенда использовать только отдельную тестовую шару и синтетические данные.

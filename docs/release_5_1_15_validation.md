# Приёмка 5.1.15

Выпуск подготовлен 30 октября 2026 года по результатам локальных логов
врача и медсестры на 5.1.14. Медицинские данные и рабочий сетевой UPD
при разработке, тестах и сборке не используются.

## Состав и профиль

- Приложение: 5.1.15. Полная поставка и отдельный установщик Windows RU/EN.
- Обязательная схема медицинской БД: 29; минимальный клиент: 5.1.15.
- `database_upgrades_disabled: false` в manifest и встроенном compiled profile.
- Для исправной схемы 28 миграция меняет только версионные метаданные.
  Клинические данные, структура таблиц, индексы и триггеры не изменяются.
- Перед миграцией выполняется проверенный backup; сбой откатывает транзакцию.
  Повышенная политика доступа сохраняется, не позволяя старому клиенту
  начать работу после неуспешной попытки. Повторный вход выполняет новый клиент.
- Схемы 26/27 проходят прежние обязательные изменения и доходят до 29.
- Пользователь закрывает все прежние клиенты перед первым запуском 5.1.15.

## PDF и диагностика

Потенциально медленные файловые операции PDF выполняются вне GUI. Сохраняются
прежний renderer, данные, путь и формат сигнала готовности; учитываются
повторные клики, закрытие окна и позднее завершение запроса.

Ошибки runtime-чтения получают безопасные числовые коды и точную стадию
execute/fetch. COMMIT/DB_WAIT дополняется ограниченными локальными кандидатами
чтения той же базы. Кандидат не объявляется владельцем SQLite-блокировки.
Новые SQL, PRAGMA и сетевые проверки ради диагностики не добавляются.
Правила COMMIT, rollback, повторов и подтверждения записи сохраняются.

## Проверки

Профильные проверки и обязательные core/ui/quality/regression выполнены
через изолированные профили Python 3.11:

| Проверка | Результат |
|---|---|
| Core | 1696 passed, 1 skipped, 60 subtests passed |
| Qt UI с AntV smoke | 1173 passed, 17 subtests passed |
| Safety fast | 538/538, без native crash и повторов после них |
| Качество и архитектура | 3/3 и 10/10 |
| Контракты установщика | 6/6; включены в штатную quality-группу CI |
| Compiled UI установщика | 17/17 RU/EN, переключение состояния и default RU |

Единственный пропуск core связан с правом Windows создавать symlink.
27 новых PDF-сценариев проверяют все шесть входов, heartbeat при задержке
файловой системы, сохранность содержания PDF, повторные клики и закрытие.
Три отдельных процесса завершаются с кодом 0 во время заблокированных
collector/mkdir/ShellExecute. Это закрывает найденный при приёмке native abort
на выходе с работающим parentless Qt-сборщиком.

На одинаковых scoped SQLite-чтениях в памяти (9 серий по 3000 вызовов)
медиана изолированного метода изменилась с 1,7 до 2,0 мкс, p95 с 1,8 до 2,1 мкс.
Число SQL осталось равным одному на вызов. Это микрозамер накладных расходов,
не измерение рабочей SMB-сети. Всплеск 10000 одинаковых ошибок дал одно
диагностическое событие и одну сохранённую категорию.

Независимые перекрёстные проверки PDF/диагностики и отдельный просмотр
миграции/упаковки не выявили блокирующих дефектов. Для установщика проверены
оба языка, длинные пути, сохранность LICENSE и отсутствие изменений
целевой папки/реестра в preview. Полная приёмка финального EXE с настоящим
payload выполняется после получения принятого full ZIP, а её отчёт хранится
рядом с артефактами сборки.

После зелёного CI и слияния PR production-пакет собирается из точного коммита
GitHub main. Full-manifest, inventory, SHA-256 и compiled smoke обоих EXE
проверяются до упаковки. Установщик принимает тот же full ZIP без изменения
байтов и проходит изолированные install/reinstall/rollback/uninstall,
compiled smoke, проверку сохранности файлов и визуальную приёмку RU/EN.

Детальные артефакты сборки, SHA и приёмки сохраняются отдельно от payload.
GitHub Release сначала получает assets в draft, затем проверяется и публикуется.

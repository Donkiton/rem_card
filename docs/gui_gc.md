# Сборка мусора в потоке интерфейса

В RemCard 5.1.5 дамп вылета 03.10.2026 09:16:08 показал уничтожение
QCalendarWidget и дочерних QWidget из фонового потока обслуживания логов
во время сборки мусора Python. Основной поток завершился с 0xc0000374.

`app/unified_main.py` отключает автоматическую сборку циклов до создания
QApplication и импорта служб, запускающих фоновые задачи. `app/gui_gc.py`
устанавливает принадлежащий QApplication контроллер: проверка раз в секунду,
сборка поколения 0 по порогу выделений, поколения 1 после девяти младших сборок,
полная сборка раз в минуту. Reference counting остается прежним.

После выхода из app.exec() автоматическая сборка не включается: окна и
завершающиеся задачи еще могут существовать. Multiprocessing-воркеры обходят
эту политику через freeze_support(); режим compiled-smoke также ее не включает.

Удаление окон при смене роли уже использует deleteLater(). Последние ссылки
на GUI-объекты нельзя освобождать в фоновых задачах; явный gc.collect() в них
также запрещен. Контроллер не перехватывает сторонние вызовы gc.collect():
callback только диагностирует нарушение и не может отменить начавшуюся сборку.

## Как разбирать повторный вылет

В обычном техническом журнале искать `[GuiGC]`:

- `installed`: версии Qt/PySide, параметры политики, идентификатор GUI-потока.
- `begin` / `end`: последовательный номер полной сборки, поколение, причина,
  число собранных объектов, длительность и счетчики. В `begin` — классы до 20
  типов верхних окон, без заголовков, objectName и данных пациентов.
  `begin` без соответствующего `end` указывает на сбой внутри сборки.
- Медленная младшая сборка (от 100 мс) также оставляет `end` с предупреждением.
- `unexpected_worker_collection`: сборка началась в другом потоке; сохраняются
  его native/Python ID и до 12 кадров Python (имя файла, строка, функция).
- `automatic_gc_reenabled`: сторонний код включил автоматическую сборку;
  контроллер снова отключил ее на очередном тике.
- `stopped`: остановка таймера перед завершением приложения.

Native ID сопоставляется с hex ID в faulthandler и дампе Windows. При повторе
сохранить журнал, logs/crashes/native и дамп AppData/Local/CrashDumps вместе.
Само наличие нарушения потока не определяет исходную запись повреждения кучи.

## Проверки

`tests/test_gui_gc.py` запускает отдельные процессы без служб БД. Регрессия
создает цикл QWidget с календарем QDateEdit, нагружает фоновый поток выделением
объектов и проверяет уничтожение только таймером GUI-потока, включая Windows Qt.
Дополнительно проверяются поколения, запрет фонового запроса, диагностика явной
фоновой сборки, повторный вход, остановка и недоступность журналирования.

Локальная проверка 03.10.2026: Python 3.11.0, PySide6/Qt 6.11.2.
146 тестов прошли (контроллер GC, unified bootstrap, смена/закрытие ролей,
изоляция Qt-окон и обслуживание журналов); ошибок и нативных падений в этом
прогоне нет. Проверка календаря выполнена также с Windows Qt platform plugin.
Статические проверки качества и 10 архитектурных проверок прошли.
Профили ОС, QSettings, журналы и пути БД перенаправлялись во временную среду;
рабочая база не использовалась. EXE для выпуска в рамках этой проверки не собирался.

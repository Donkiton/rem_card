# Единый вход: результат реализации 13.09.2026

Ветка `codex/unified-entry`, исходный коммит `daeb814bccbcd02312f8814cbbd67f15697c3b84`. Изменения находятся в рабочем дереве. Это экспериментальная поставка, без публикации релиза и без изменения рабочей базы.

## Поведение

- `RemCard.exe` открывает настройку пути при первом запуске, затем загрузку и выбор четырёх ролей. Отдельным остаётся `RemCardUpdater.exe`.
- Один экземпляр на ПК. «Назад» сектора 8 сохраняет прежнюю навигацию. Отдельная кнопка «Роли», настраиваемая через отображение сектора 8, возвращает к выбору ролей после завершения фоновых задач. У каждой роли новый контейнер; геометрия приветствия и ролей сохраняется отдельно.
- В Центре управления доступны полное/короткое название учреждения, изменение пути с перезапуском и технические работы. Название больницы изначально пустое, ОРИТ сохраняется.
- Название учреждения исключено из release snapshot. Даже старый пакет, содержащий `institution/identity`, не перезаписывает учреждение получателя и не добавляет чужое название в новую базу.
- Техработы сразу запрещают новые входы. Работающий клиент после получения состояния даёт 60 секунд для сохранения, затем завершает роль. Несохранённые формы не восстанавливаются автоматически. Принятые операции ожидаются до доказанного результата; неизвестный исход блокирует освобождение базы.
- Состояние доставляется через `QFileSystemWatcher`, с резервной проверкой раз в 30 секунд. Файловое уведомление не является доказательством освобождения: обслуживание требует исключительной OS-блокировки, а роли удерживают совместные блокировки весь срок владения соединениями.
- При недоступной сети разрешён подтверждённый локальный аварийный запуск из подходящей копии. Проверяется её привязка к выбранной базе. Центральные scheduler’ы и отправка outbox выключены до bootstrap. Проверки общей базы, обновлений и её обслуживания в локальной роли запрещены. Для подключения нужно выйти к выбору ролей и заново пройти центральный допуск; объединение аварийных изменений использует существующий явный процесс.
- Граница между полностью локальным и сетевым хранилищем требует чистого перезапуска процесса: старые модули сохраняют пути в константах импорта. Выход через «Роли» из local-only завершает ресурсы и перезапускает приветствие; обычное переключение ролей остаётся внутри одного окна. Если процесс уже импортировал пути другой базы, local-only bootstrap сначала требует перезапуска. Неуспешный запуск нового процесса не разрешает использовать старые пути.
- Уже известные техработы или повреждённое состояние доступа не обходятся локальным fallback. Ошибка после центрального допуска не запускает второй контейнер поверх неосвобождённого первого.
- Совместимость проверяется до writable bootstrap, включая минимальную версию клиента. При найденном обновлении «О программе» заменяется кнопкой обновления; обновление завершает процесс и перезапускает единый EXE.

## Надёжность

Добавлен реестр принятых записей с идентификаторами операции и сеанса. Итог записи устанавливается до уведомления интерфейса. Ошибка callback не повторяет committed-транзакцию. Фоновое освобождение коек переведено в управляемую очередь. При выходе учитываются заменённые контейнеры оперблока, очереди, синхронные записи и фоновые читатели. Неостановленные ресурсы сохраняются для повторного drain. Для форм оперблока добавлена проверка ожидаемых ревизий перед сохранением.

Диагностические события связывают вход, принятые сохранения, результаты и освобождение ресурсов с сеансом. Новые события не записывают содержимое назначений и полные SQL-параметры.

## Границы приёмки

- Фактическая больничная SMB-сеть и несколько физических ПК не использовались. Блокировки проверены независимыми локальными процессами; сетевую приёмку нужно проводить на отдельной тестовой общей базе.
- Старые EXE не знают нового протокола. Для гарантии техработ все рабочие станции должны перейти на новую версию. Наличие старого lock-файла блокирует обслуживание, но не делает старые бинарники участниками нового протокола.
- Старый установленный checker ожидает шесть EXE. Первую двухфайловую поставку нужно установить вручную либо доставить через промежуточную совместимую версию. Новый checker/updater поддерживает оба формата.
- Сборка рабочего дерева помечена `TEST_WORKTREE_ONLY.txt`, не содержит публикационного `ready.ok` и не отправляется в сетевой UPD. Рабочий релиз не выпускался.

Первоначальная сборка `scripts/build_release.py --test-worktree --progress-json` завершилась с кодом 0. В `dist/Prog` ровно два EXE; проверены совпадение hash snapshot/manifest и отсутствие institution/identity в пакете. SHA-256 первоначального `RemCard.exe`: `b24a7e74160ef5accb6922045a474bd662d47464350bc7e48dd57f79f02529f5`.

После исправлений: UI — 739 тестов и 11 subtests; целевые проверки создания базы, первого запуска, навигации и аргументов пройдены. Оба собранных EXE прошли smoke.

## Что изменено

Сохранены входные классы `DoctorRemCardWidget` и `OrdersWidget` и их прежние
пути импорта. Каждый остаётся одним `QWidget` с прежними сигналами и общим
состоянием. Методы распределены по функциональным примесям без новых объектов
состояния, посредников для вызовов, динамической подмены globals и изменений БД.

| Координатор | Было строк | Стало строк | Определения методов |
|---|---:|---:|---:|
| `ui/doctor_view/doctor_remcard_widget.py` | 4710 | 301 | 218, включая getter/setter `current_date` |
| `ui/doctor_view/orders_widget.py` | 4646 | 158 | 196 |

Это перенос реализации; общий объём логики не сокращён на разницу этих чисел.
Примеси по-прежнему связаны общим состоянием и предназначены для использования
только через соответствующий входной класс.

| Модуль | Ответственность |

Вспомогательный `_OptimisticAdminChanges` перенесён в `administration_actions`.
Глубокие импорты внутренних функций и констант через старые монолитные модули
не сохраняются как внешний API; внутренние потребители используют новые пути.
Локальные относительные импорты в перенесённых методах преобразованы в
канонические абсолютные пути с сохранением прежней цели.

## Сохранённые ограничения

- Подтверждённые назначения передаются через `committedOrdersBalanceReady`;
  карта принимает их как немедленную основу баланса, затем сверяет снимок по
  `change_id`. Сохранены предварительное состояние новой карты и отсечение
  устаревших/неполных снимков через `BalanceSnapshotSync`.
- Локальные черновики, защита при переходе между пациентами, отметки выполнения,
  очереди записи и проверки устаревших запросов сохраняют прежний порядок.
- Qt-сигналы, свойства, владение объектами, порядок завершения фоновых задач и
  ленивое создание полной карты сохранены.
- Клинические правила, рабочие данные, темы, AntV и выпуск EXE не изменяются.

Core-сбои: тест «быстрая операция не журналируется» превысил малый временной
порог при параллельном прогоне; в тесте временного snapshot-gate Windows вернула
`WinError 32` при удалении тестового файла. Оба прошли повторно без изменения
кода. Исходные отчёты с ошибками сохранены: повторные адресные проверки не
представляются как полностью зелёный повтор всего набора. Пропущен опциональный
smoke-тест реального AntV/QtWebEngine, требующий отдельного opt-in запуска.

Независимая проверка подтвердила эквивалентность методов и helper-класса,
сохранение Qt-сигналов и корректный порядок наследования для `eventFilter`;
проверены оставшиеся относительные импорты и защитные отказы source-reader.

Статические safety-проверки используют `read_widget_source` из
`scripts/regression_checks/source_inspection.py`: читают реально подключённые
примеси, сохраняя текст проверяемых методов. Не подключённые файлы не участвуют;
неразрешённое наследование и перекрытие методов требуют явного рассмотрения.
Два теста проверяют обнаружение потерянного модуля и перекрытия метода.
Прежние assertions сценариев сохранены; места подмены зависимостей перенесены
в модули реализаций. Карта `docs/codemap/` также обновлена.

Изоляция прогонов: отдельные BAZA, QSettings, настройки оформления, конфигурации
базы, журналы, `LOCALAPPDATA`, `APPDATA`, `ProgramData`, `USERPROFILE`, `HOME`,

## Восстановление

Базовые файлы доступны без изменения рабочего дерева:

```powershell
git show e8cf5e2fb7e0c40b81a3042530c1e8a65a49dc3f:ui/doctor_view/doctor_remcard_widget.py
git show e8cf5e2fb7e0c40b81a3042530c1e8a65a49dc3f:ui/doctor_view/orders_widget.py
```

После сохранения этого шага отдельным коммитом откат выполняется через
`git revert <SHA-коммита>` в `rework`. Перенос методов, импорты потребителей и
адаптация проверок образуют единое изменение. Не следует восстанавливать один
старый монолит поверх новых модулей. `main` сохраняется до отдельного решения
владельца о завершении всей последовательности рефакторинга.

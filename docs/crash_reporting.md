# Локальные логи и аварийные отчёты RemCard

Обычные runtime-логи всегда сначала записываются локально, рядом с установленной программой. Их создание не требует доступа к выбранной сетевой папке данных:

```text
<папка программы>\logs
  ├─ doctor_YYYYMMDD.log
  ├─ nurse_YYYYMMDD.log
  ├─ operblock_*.log
  ├─ startup.log
  ├─ updater_YYYYMMDD.log
  ├─ metrics_YYYYMMDD.jsonl
  ├─ audit_YYYYMMDD.jsonl
  ├─ crashes
  │    ├─ outbox
  │    ├─ sent
  │    ├─ sessions
  │    └─ native
  └─ migrated-appdata
       ├─ logs
       └─ crash-outbox
```

Обычные журналы `.log` предназначены для чтения человеком. Метрики и audit/crash-события остаются в JSONL/JSON: это структурированные записи с фиксированными полями, которые валидируются и обрабатываются автоматически.

`crashes\outbox` содержит ожидающие доставки crash-отчёты. После успешной атомарной записи в общую папку отчёт перемещается в локальный `crashes\sent`, поэтому локальная копия не теряется. Доставленные локальные отчёты хранятся 180 дней; ожидающие отчёты и данные активных/аварийных сессий ротация не удаляет.

Общий диагностический каталог остаётся внутри выбранной папки данных:

```text
<папка данных>\logs\diagnostics\crashes
  ├─ incoming
  ├─ processed\YYYY\MM
  ├─ summaries
  └─ quarantine
```

Локальный `audit_*.jsonl` является первичной записью. Его копирование в `<папка данных>\logs` выполняется фоновым best-effort worker и не блокирует интерфейс при медленной или недоступной сетевой папке.

Crash-report не содержит полного общего лога, SQL, локальных переменных, текста медицинских форм, идентификаторов госпитализации или абсолютных путей. События одной причины объединяются по техническому fingerprint.

При первом запуске после перехода со старой схемы содержимое `%LOCALAPPDATA%\RemCard\logs` и `%LOCALAPPDATA%\RemCard\crash-outbox` копируется в `<папка программы>\logs\migrated-appdata`. Исходные AppData-файлы в этом релизе не удаляются. Ожидающие crash-отчёты дополнительно импортируются в новый активный `crashes\outbox`.

Если папка программы недоступна для записи, приложение использует `%TEMP%\RemCard\logs`. Это не происходит бесшумно: предупреждение попадает в основной лог/консоль, а `%LOCALAPPDATA%\RemCard\log_location.json` сохраняет предпочитаемый и фактический пути вместе с причиной fallback.

## Обработка через PowerShell

По конфигурации установленной программы:

```powershell
python scripts\process_crash_reports.py `
  --config "D:\RemCard\remcard_data_path.json"
```

По точному пути к папке данных:

```powershell
python scripts\process_crash_reports.py `
  --data-root "\\SERVER\Share\RemCardProductionData"
```

Обработчик проверяет JSON, группирует события, создаёт `crash-summary_*.md`, переносит исходники в `processed` и помещает некорректные файлы в `quarantine`. Обработанные отчёты, сводки и карантин хранятся 180 дней. Файлы из `incoming` сначала обрабатываются и только затем могут попасть под очистку.

Обычный успешный запуск и штатное закрытие приложения crash-report не создают.

REMCARD — ИЗОЛИРОВАННАЯ ПРОВЕРКА АВАРИЙНОГО РЕЖИМА

Это отдельная тестовая сборка. Она работает только с синтетической базой внутри своей папки и не должна использоваться для настоящих пациентов.

Текущий единый вход содержит четыре роли: врач, медсестра, плановый и экстренный оперблок. Настройки и администрирование открываются из единого окна. Все роли работают с тестовыми данными этого стенда.

Подготовка

1. Полностью извлеките ZIP в отдельную обычную папку на локальном диске этого компьютера.
2. Не запускайте START_TEST.cmd внутри ZIP, с сетевого диска или из программы просмотра архива.
3. Python устанавливать не нужно. Запускайте START_TEST.cmd обычным двойным щелчком, не от имени администратора.
4. При подключении или отключении тестовой сети Windows отдельно покажет запрос контроля учётных записей (UAC). Разрешение относится только к уникальному тестовому SMB-ресурсу этой распакованной копии.

Первый запуск и подготовка резерва

1. Откройте START_TEST.cmd.
2. Выберите «1  Подключить / восстановить тестовую сеть».
3. Выберите «2  Запустить единую тестовую RemCard», затем в программе выберите роль врача.
4. В базе уже есть вымышленный пациент «Тестов Пациент Учебный», история «ТЕСТ-001». Можно создать ещё одного вымышленного пациента и проверить обычную работу.
5. Полностью закройте RemCard с открытой ролью врача.
6. Снова выберите «2  Запустить единую тестовую RemCard», затем выберите роль медсестры при подключённой тестовой сети.
7. Не работайте в программе около минуты. В тестовой сборке резерв обновляется с интервалом 30 секунд после не менее 5 секунд бездействия.
8. В меню выберите «4  Обновить состояние». Строка «Резерв для аварии» должна показать наличие файлов и время обновления. Полная проверка копии выполняется при входе в аварийный режим.

Имитация сбоя сети

1. Оставьте RemCard с открытой ролью медсестры или полностью закройте её и запустите снова после отключения — можно проверить оба сценария.
2. В меню выберите «3  Отключить тестовую сеть».
3. Это удаляет только уникальный общий ресурс этой тестовой копии. Файлы Database и State не удаляются.
4. До включения аварийного режима медсестрой вход в роль врача без сети заблокирован. После ввода аварийного пароля врач на этом же ПК открывает общую локальную сессию.
5. При входе в роль медсестры без сети RemCard должна предложить аварийный режим. Аварийный пароль тестовой базы: test-2026
6. Сделайте только вымышленные изменения. В секторе 8 слева, рядом с репортом, доступна кнопка «Аварийный режим» без подсказки при наведении — и у врача, и у медсестры.

Отдельно можно оставить роль врача открытой и отключить тестовую сеть: предупреждение о недоступной базе не должно размножаться. При создании общей аварийной сессии уже открытая роль врача должна перейти на локальные данные после повторного входа в роль.

Восстановление и перенос тестовых изменений

1. Если врач работает в общей аварийной сессии на этом ПК, его можно оставить открытым. Сохраните или отмените черновики назначений.
2. В меню выберите «1  Подключить / восстановить тестовую сеть». Запуск RemCard сам сеть не подключает.
3. Если программа открылась при полностью недоступной сетевой папке, фоновые проверки сети отключены. Нажмите «Аварийный режим» в секторе 8 и подтвердите безопасный перезапуск для проверки сети. После него открывается та же аварийная сессия. В режиме с разрешёнными сетевыми проверками также может появиться сообщение «Сеть восстановлена»: «Перейти сейчас» или «Остаться».
4. Можно также нажать «Аварийный режим» в секторе 8 у врача или медсестры. Введите пароль test-2026. В этом же окне сначала проверяется основная база; подтверждение станет доступно только после успешной проверки.
5. После подтверждения программа сохранит принятые записи, завершит другие окна общей локальной сессии и предложит просмотр изменений. Если у врача есть несохранённый черновик, сначала сохраните или отмените его.
6. Подтвердите перенос только выбранных синтетических пациентов. После успешного завершения программа перезапустится с тестовой сетевой базой. Повторный вход в любую роль также должен открыть уже обновлённую сетевую базу.
7. Отмена просмотра сохраняет локальные данные и ожидание. «Продолжить работу» возвращает в аварийную сессию; «Закрыть RemCard» сохраняет ожидание до следующего запуска. Эти действия сами по себе не означают, что данные уже перенесены.

Завершение

Дополнительные сценарии для нового единого входа

А. Нет копии: распакуйте ZIP в новую папку, не входите медсестрой, отключите тестовую сеть. Врач должен получить указание продолжить работу на ПК медсестры; выбор медсестры должен показать отсутствие копии, без создания пустой базы.

Б. Обрыв у врача: до активации аварийной сессии подготовьте копию медсестрой при включённой сети, затем перейдите во врача. Отключите сеть и обновите данные. Ожидается предупреждение и возврат к выбору ролей без аварийного предложения врачу. Выберите медсестру: проверка даты/возраста копии, пароль test-2026, безопасный перезапуск и локальная работа.

В. Смена ролей: после активации медсестрой сохраните вымышленные изменения и войдите врачом. Должна открыться та же локальная сессия без повторного аварийного пароля. Смена режима может потребовать перезапуска. Полностью закройте и снова запустите программу без сети — локальные изменения должны сохраниться.

Г. Недельная копия: на отдельной распаковке подготовьте копию, закройте RemCard и отключите сеть. До создания активной сессии откройте в Блокноте State\Emergency\standby\standby_metadata.json и измените только updated_at на дату недельной давности, сохранив формат даты. Войдите медсестрой: ожидается дата/возраст/предел 3 суток и отказ без удаления файлов. Метаданные активной сессии не редактируйте. Для следующего чистого сценария распакуйте ZIP заново в другую папку.

Д. Оперблок: отдельно для плановой и экстренной роли проверьте вход с сетью, создание вымышленного случая, обрыв при открытом случае, сохранение и повторный вход без сети, затем восстановление ресурса и предусмотренный интерфейсом возврат/перенос. Оперблок использует собственный локальный механизм; не ожидайте парольного сценария медсестры РАО. Локальное состояние оперблока также находится внутри State этого стенда.

Для независимых сценариев распаковывайте исходный ZIP в новые папки. Не копируйте уже запущенный стенд с активной сессией: её пути относятся к исходной папке.

Сначала закройте окна тестовой RemCard. В меню выберите «0  Завершить и убрать только тестовый сетевой ресурс». Это не удаляет тестовую базу, аварийную сессию и логи. Повторная очистка безопасна, если ресурс уже отсутствует.

При ошибке можно передать разработчику всю папку State: в ней только состояние этой синтетической сборки. Основные логи находятся в State\Logs, дополнительное локальное состояние — в State\LocalAppData\RemCard. Не добавляйте в тестовую базу реальные сведения о пациентах.

Команды для автоматической проверки

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-RemCard.ps1 -Action Status
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-RemCard.ps1 -Action Connect
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-RemCard.ps1 -Action Disconnect
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-RemCard.ps1 -Action Cleanup
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-RemCard.ps1 -Action RemCard
